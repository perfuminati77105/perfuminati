# 2026-08-11 — Phase 9: Full Static QA Pass

## Scope
This is the "testing I can do without a live store" gate, run after all 8
customization phases (brand foundations through cart) were complete, against
the full, final theme — not just the files changed in a single phase.

## What was tested and how

### 1. Shopify Theme Check (Liquid/JSON linter)
```sh
npx shopify theme check
```
**Result: 172 files inspected, 0 errors, 8 warnings.**

The 8 warnings are the exact same ones present in the untouched Dawn
v15.5.0 baseline (see `docs/2026-08-10-project-setup.md`) — `VariableName`
(2), `UnusedAssign` (2), `UndefinedObject` (2), `OrphanedSnippet` (1), all
in stock Dawn files we never touched
(`sections/main-article.liquid`, `sections/main-list-collections.liquid`,
`sections/main-product.liquid`, `sections/main-search.liquid`,
`layout/theme.liquid`, `snippets/quick-order-product-row.liquid`). Zero
new warnings or errors were introduced across all 8 phases of
customization.

### 2. JSON syntax validation (all files, not just edited ones)
A small Node script walked the entire repository (excluding
`node_modules`/`.git`) and ran `JSON.parse` on every `.json` file found.

**Result: 77 files checked, 0 invalid.**

### 3. CSS brace-balance check
For every CSS file edited this session (`assets/base.css`,
`assets/component-card.css`, `assets/component-badges.css`), counted `{`
vs `}` occurrences to catch any unclosed rule from manual edits.

**Result: all three files balanced** (base.css 640/640, component-card.css
123/123, component-badges.css 5/5).

### 4. Manual overflow/responsiveness review
Since `shopify theme check` doesn't lint CSS, reviewed all CSS added or
modified this session by hand for the specific risks called out in the
original testing checklist (horizontal scroll, overflow, buttons escaping
containers, text wrapping):

- **Badge stack** (`assets/component-badges.css`): `.product-badge` has
  `max-width: 100%`, `overflow: hidden`, `text-overflow: ellipsis` on
  cards (prevents a long badge label from forcing card width to grow or
  overflowing); PDP context overrides to `white-space: normal` so it wraps
  instead of truncating, appropriate for its roomier layout.
- **Hover-reveal quick add / image crossfade** (`component-card.css`):
  transform/opacity-only changes inside an already `overflow: hidden`
  media container — hover scale (1.04x) cannot visually escape the card,
  confirmed by reading the existing `.card .card__inner .card__media {
  overflow: hidden }` rule this relies on.
- **`page_width: 1400`** (Phase 1): within Dawn's supported/tested range
  (1000–1600 per its own schema), not a value we invented; Dawn's grid CSS
  is written against the `--page-width` custom property throughout, not
  hardcoded pixel assumptions.
- **Uppercase nav/button typography**: no fixed-width containers were
  added around text; Dawn's existing button/nav CSS already uses
  `min-width` (not `max-width`) and flexible padding, so longer uppercase
  text can only grow a control, not overflow it.
- Grepped the whole `assets/` folder for `1200px`/`1400px` literals to
  check for anything hardcoded against the *old* default page width that
  might conflict with the new 1400px setting — the only matches were
  unrelated, pre-existing Dawn media-query breakpoints (viewport-based,
  not page-width-based), not something our settings change affects.

## What is explicitly NOT covered by this pass

This was static/code-level verification only. The following require a
live store connection (`shopify theme dev`) and are deferred to Phase 10:

- Actual rendered visual appearance in a browser (colors, fonts, spacing
  "looking right")
- Real interaction testing: hover states, the cart drawer open/close
  animation, mobile menu drawer, filter drawer, quick-add modal
- Testing across real device viewports (this pass reasoned about CSS
  rules, not actual rendered layout at 375/768/1024/1440px)
- Badge behavior with real metafield values set on real products (the
  metafield definitions themselves don't exist yet — see
  `docs/2026-08-10-metafields.md`)
- Font rendering verification (`playfair_display_n4` / `jost_n4` IDs are
  unverified against Shopify's live font service — see Phase 1 notes)
- Add to cart / checkout flow, since that requires a real cart session
  against a live store
- Lighthouse/performance testing (requires a served, live page)

No fixes were needed as a result of this pass — everything reviewed was
